# rust-shard: tile-world shard core (classic top-down RPG MMO)

**Status: VERIFIED** on SpacetimeDB 2.14.0 with Rust 1.97.1 / wasm32 (Linux): the Meadowmere fixture
publishes, seeds and is played end to end by two Godot 4.7.2 clients in 2D and 3D
(`python tools/shard/fixture_game.py live --publish --godot $GODOT [--renderer 3d]`).

A clean-room, game-agnostic MMO core for tile-based worlds with towns, portals and NPCs. It grows out of
`rust-single` (intent movement, scheduled tick, `tick_health`, AOI cells, admission) and adds:

| Area | Module | What |
|---|---|---|
| Maps | `core/maps.rs`, `core/world.rs` | Maps, portals, map exits, safe zones, respawn points; tiles kept in private tables |
| Movement | `core/movement.rs` | Tile collision (walkable set per map) and body blocking |
| NPCs | `core/npc.rs` | Seeded NPCs that wander inside the tick |
| Chat | `core/chat.rs` | `say` reducer with a per-player rate limit |
| Combat | `core/combat.rs` | `attack`, monster spawn/chase passes, HP regen, death and respawn, XP/levels |
| Items | `core/items.rs` | Ground drops with decay, `pick_up`, `use_item`, private `my_inventory` view |
| Seeding | `core/seed.rs` | Operator-only `seed_*` staging reducers; worlds are data, not code |
| Rules | `core/rules.rs`, `core/tables.rs` | Numbers and table definitions |

The world comes from a `mmo-core-world/1` document (see `docs/SHARD_CORE.md`) that
`tools/shard/seeder.py` sends through the seed reducers. The template ships **no third-party game data**:
the test world (Meadowmere) is generated by `tools/shard/fixture_game.py`.

Game-specific server rules go in sibling modules next to `core/`. Keep `core/` vendor-clean: change it in
the kit and re-vendor with `tools/shard/vendor_core.py` (see `docs/SHARD_CORE.md`, "Vendoring").
Rules this module follows: `rules/rust-module.md`.
